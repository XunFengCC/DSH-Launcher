# 2026-09-16 反馈模块验收

DSH 的 App 菜单和帮助菜单均提供“问题反馈…”。收件地址由发行配置提供；本文记录模块边界与可复核的验证，不包含维护者的私人联系信息。

## 实现与边界

- 原生AppKit面板收集描述，可预览或存储报告。自动字段只有App版本/build、macOS、架构和生成时间；不读取实际会话或运行日志。
- 用户可能有意填写账号/地址以帮助复现，因此描述原文和缩进换行保留。预览显示完整内容，GitHub入口说明公开可见。早期过滤手写描述的方案会破坏复现上下文，因此撤销；自动字段由明确来源范围限制。
- 系统邮件草稿使用配置的收件地址，正文与文本附件包含完整报告。使用NSSharingService并保留实例，不依赖无法带附件的mailto链接；客户端不可用时给出手动处理说明并在Finder定位文件。App不代替用户发送。
- 地址验证只接受`https://github.com/<owner>/<repo>/issues/new`，错误配置不会被解释成其他页面。当前配置指向本项目公开Issue页面，用户仍需检查并自行提交。
- 本地报告存入`~/Library/Application Support/DSH Launcher/Feedback/`，UUID文件名避免同秒覆盖，目录/文件权限为0700/0600。

## 验证

- 最终反馈源码与主入口的macOS14/arm64类型检查通过；纯Foundation测试覆盖配置、目标URL拒绝、原文/缩进保留、完整邮件报告与附件、独立落盘和权限。
- 用独立AppKit测试程序加载`FeedbackCore.swift`与`FeedbackWindow.swift`，不加载主AppDelegate、不启动Harness。预览和邮件草稿验证通过：配置收件地址、报告正文和附件一致；草稿未发送。
- 界面布局回归发现垂直NSStackView的对齐设置让标题右对齐，修为leading并为正文/输入区明确宽度；重新编译后确认左对齐且内容无裁切。
- 真实系统存在邮件客户端，未通过修改系统配置强制制造“无客户端”；该回退分支代码已核查，但未作真实环境点击验收。

## 构建与运行态

标准`buildApp.sh`的Swift编译/链接通过，但在原有图标步骤遇到本机sips无法解析既有SVG（exit13）；源SVG未修改，同输入复现。本轮用独立验收App避免把图标工具修复扩展成反馈任务。最终全量发行构建仍需在发版时解决/复核该既有图标路径，并完成既有发布审查项。

当时验证使用独立反馈面板程序，未替换安装 App、服务或发行包。此记录属于反馈子模块验收，不能当成整包首次运行证明。2026-10-04 当前完整构建已复核原图标步骤成功，历史 `sips` 失败未重现，详见发行验证。
